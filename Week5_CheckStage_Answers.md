### 1. What is an embedding, in your own words?
**Answer:**  
An embedding is a dense mathematical vector (a long list of floating-point numbers, such as 1536 floats for OpenAI's `text-embedding-3-small`) that represents the semantic meaning of a piece of text in high-dimensional space. Generated by a neural network, embeddings position concepts with similar meanings close together in vector space, allowing computers to perform mathematical operations (like distance and cosine similarity) on human ideas rather than merely matching raw characters.

---

### 2. Why does cosine similarity work better for comparing meaning than checking if the same words appear?
**Answer:**  
Keyword matching (like SQL `LIKE` or basic string containment) only checks for verbatim character matches and completely fails when synonyms, metaphors, or different phrasings are used. For example, *"a boy learns spells at an academy"* and *"a young wizard attends a magic school"* share almost no words in common, but mean the exact same thing. Cosine similarity calculates the geometric angle between the two semantic embedding vectors:
$$\text{cosine\_similarity}(u, v) = \frac{u \cdot v}{\|u\| \|v\|}$$
Because both vectors point in almost the exact same direction in concept space, cosine similarity produces a high score (close to 1.0) regardless of the specific vocabulary chosen.

### 3. Why can't you just search a growing set of embeddings with a Python for-loop forever — what does a vector database give you that a list doesn't?
**Answer:**  
A linear Python `for` loop (exact brute-force $k$-NN) has an $O(N \cdot D)$ time complexity for $N$ vectors of dimension $D$. While fast for 10 or 100 items, searching millions of 1536-dimensional vectors causes unacceptable latency and high memory overhead.  
A vector database (like Chroma, FAISS, Pinecone, or Qdrant) provides:
1. **Approximate Nearest Neighbor (ANN) Indexing:** Hierarchical Navigable Small World (HNSW) graphs or inverted file indexes (IVF) that find nearest neighbors in sub-linear logarithmic time ($O(\log N)$).
2. **Metadata Filtering:** The ability to execute hybrid searches combining structured relational conditions (e.g. `category == 'Fantasy'`) with vector distance in a single query.
3. **Persistence and Memory Management:** Efficient disk-backed caching, snapshotting, and concurrent multi-user querying.

### 4. What is chunking, and why does chunk size matter?
**Answer:**  
Chunking is the process of breaking large documents into smaller, overlapping segments of text prior to embedding and indexing.  
Chunk size matters because:
- **If chunks are too large:** The embedding vector is forced to summarize too many disparate topics, diluting semantic specificity and eating up large portions of the LLM's prompt context window.
- **If chunks are too small:** The text gets fragmented mid-sentence, losing necessary context, antecedent references, and grammatical meaning.
- **Overlap (e.g. 10–15%):** Ensures that sentences split across chunk boundaries remain intact in at least one adjacent chunk.

### 5. What are the 8 stages of a RAG pipeline, in order?
**Answer:**  
1. **Document Loading:** Ingesting raw source files (PDFs, text files, API endpoints, SQL databases).
2. **Chunking / Text Splitting:** Dividing documents into coherent, overlapping chunks.
3. **Embedding:** Passing each chunk to an embedding model to compute vector representations.
4. **Vector Storage:** Persisting the chunk vectors, text strings, and metadata into a vector database (e.g. Chroma).
5. **Retrieval:** Embedding the user's question and executing an ANN search to retrieve the top-$k$ most relevant chunks.
6. **Context Construction:** Assembling the retrieved chunks into a prompt template bounded by strict system instructions.
7. **Answer Generation:** Sending the prompt to the LLM (e.g., Claude or GPT) to synthesize a grounded answer.
8. **Source Attribution:** Extracting and returning document citations/sources alongside the generated response so users can verify the information.

---

### 6. Why is it important to explicitly instruct the model to only use the provided context?
**Answer:**  
Without explicit grounding constraints, LLMs default to their pre-trained parametric memory. If a question is slightly outside the catalog or unanswerable from the retrieved text, the model will confidently hallucinate plausible-sounding answers based on general training data. Explicitly commanding the model: *"Answer using ONLY the context below. If not found, say 'I don't have that information.' Do not use outside knowledge."* forces the model to abstain whenever the retrieved context lacks sufficient evidence.

### 7. What's the difference between a retrieval failure and a generation failure in a RAG system, and why does the distinction matter when debugging?
**Answer:**  
- **Retrieval Failure:** The vector search returned irrelevant or incomplete chunks that do not contain the answer. (The LLM never stood a chance because it was never handed the necessary facts).
  - *Fix:* Modify chunk size/overlap, switch embedding models, introduce metadata filters, or add BM25 hybrid search.
- **Generation Failure:** The correct chunks were successfully retrieved and placed in the prompt, but the LLM hallucinated, missed key details, or ignored the facts.
  - *Fix:* Refine prompt instructions, lower temperature to `0.0`, provide few-shot examples, or use a stronger model.
- **Why it matters:** Attempting to fix a retrieval bug by tweaking the LLM system prompt is ineffective; engineers must isolate which half of the pipeline failed before applying a fix.

### 8. What is source attribution, and why does it matter for trust in an AI answer?
**Answer:**  
Source attribution is the practice of explicitly citing the specific document name(s), chapter, page, or database IDs from which the retrieved chunks originated, returning them alongside the generated text.  
It matters because:
1. **Verifiability:** Allows users and domain experts to cross-check claims against original primary sources.
2. **Auditability & Compliance:** Crucial in enterprise, legal, medical, and financial environments where unverified AI output carries legal liability.
3. **Debugging:** Helps developers verify which knowledge assets influenced the model's response.

### 9. What does `git revert` do differently from manually editing the file back to its old state?
**Answer:**  
- **Manual editing:** Creates a new commit that looks like brand-new development work, obscuring the fact that a regression was caught and rolled back.
- **`git revert`:** Explicitly generates an automated inverse commit (e.g. `Revert "feat: add feature X"`). It transparently documents the software lifecycle in the git history, showing exactly which commit introduced the bug, why it was backed out, and when it occurred, without losing the record of the original attempt.

---

### 10. Why is `git reset` risky on a shared branch like main, while `git revert` is not?
**Answer:**  
- **`git reset` (Dangerous on shared branches):** Rewrites commit history by moving the branch pointer backward and deleting commits. If pushed to a shared remote branch, it requires force-pushing (`git push --force`), which desynchronizes other team members' local repositories, orphans commits, and violates repository branch protection rules.
- **`git revert` (Safe everywhere):** Appends a brand-new commit forward in time that neutralizes the unwanted changes. It preserves existing commit hashes, requires no history rewriting or force-pushes, and seamlessly merges through standard Pull Requests.
