# Week 5 — Part A: Embeddings Fundamentals

## Overview
Everything in RAG (Retrieval-Augmented Generation) depends on turning text into a list of floating-point numbers (vectors) that capture semantic meaning.

## Key Concepts
- **Embedding:** A vector (e.g. 1536 floating point numbers for `text-embedding-3-small`) representing semantic meaning generated by an embedding model.
- **Semantic Similarity:** Measuring how close two texts are in conceptual meaning rather than verbatim keyword matching.
- **Cosine Similarity:** A standard metric measuring the cosine of the angle between two vectors:
  $$\text{cosine\_similarity}(A, B) = \frac{A \cdot B}{\|A\| \|B\|}$$
  - Returns `1.0` for identical directions (identical meaning).
  - Returns values close to `0.0` for unrelated topics.
- **Search Advantages:** Unlike SQL `WHERE title LIKE '%keyword%'` queries which fail when synonyms or paraphrasing are used, vector search matches user intent (e.g., querying *"space adventure books"* finds *"an interstellar journey"*).

## Practice Observations
1. `len(v1)` yields 1536 floats. Individual numbers carry no human-readable meaning on their own; semantics emerge only when vectors are compared via distance/similarity functions.
2. Sentences sharing conceptual meaning ("young wizard attends magic school" and "boy learns spells at academy") yield high cosine similarity scores (typically > 0.85).
3. Unrelated sentences yield significantly lower similarity scores (typically < 0.25).
4. Sentences with inverted sentiment ("I loved this book" vs "I did not love this book") share moderate-to-high semantic similarity because they belong to the same topic domain (book review), demonstrating why prompt grounding and classification layers complement raw retrieval.
